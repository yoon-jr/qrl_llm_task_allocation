# LLM Task Allocation · 강화학습 환경 프로토타입

LLM 요청의 **정답·지연·출력량 기반 비용을 함께 고려하는 환경과 실험 루프**를 구성한 연구 초안입니다. Random, Q-learning, QRL, DQN을 연결하는 코드 구조를 포함합니다.

**현재 상태: 구현 진행 중인 프로토타입.** 행동 공간이 하나이고 일부 에이전트 학습이 미구현되어 있어, 완성된 작업 할당 최적화·강화학습 성능 향상·탄소 절감 성과로 해석하지 않습니다.

## 코드에서 확인할 내용

| 구성 | 역할과 현재 상태 |
|---|---|
| [env.py](env.py) | 작업 로드·LLM 호출·보상·로그 환경. 현재 main에서 사용하는 환경 |
| [env_gemini.py](env_gemini.py) | Gemini 환경의 별도 구현. SDK import 정리 필요 |
| [train.py](train.py) | 에이전트 종류별 반복 실행 |
| [agents/dqn.py](agents/dqn.py) | DQN 네트워크·리플레이·업데이트 구현 |
| [agents/qlearning.py](agents/qlearning.py) | 현재 행동 0 반환, `learn` 미구현 |
| [agents/qrl.py](agents/qrl.py) | 현재 행동 0 반환. 이름만으로 양자 강화학습 구현을 의미하지 않음 |
| [main.py](main.py) | 비교 실행·그래프·CSV 저장 흐름 |
| [data/sample_tasks.json](data/sample_tasks.json) | 작업 입력 예시 |

## 설계한 실험 흐름

1. JSON/JSONL의 `problem`을 작업 목록으로 읽습니다.
2. 남은 작업 수, 직전 처리시간, 직전 출력량을 상태로 제공합니다.
3. 에이전트의 행동을 받아 LLM 요청을 처리합니다.
4. 응답·지연·비용 추정값을 기록하고 보상을 계산합니다.
5. 정책별 결과를 집계하도록 구성했습니다.

현재 `Discrete(1)`이므로 행동은 0 하나뿐입니다. 모델·작업·출력 예산 중 무엇을 선택할지에 따라 행동이 달라지는 구조가 아직 없어, 실질적인 할당 정책 비교는 성립하지 않습니다.

## 지표 정의 · 구현 기준

| 지표 | 현재 계산 | 해석 제한 |
|---|---|---|
| 처리시간 | LLM 요청 구간의 경과시간 | 네트워크·공급자 응답 지연 포함 |
| 출력량 | `len(text_out.split())` | 공백 분할 개수이며 실제 API 토큰 수와 다름 |
| 에너지 추정 | `출력량 × power_per_token` | 기본 계수 0.00005를 사용한 가정값. 전력 실측이 아님 |
| 탄소 추정 | `에너지 추정 × carbon_intensity` | 기본 계수 0.47. 실제 전력원·장비 측정 기반 값이 아님 |
| 보상 | `정답 보상 − 0.01 × 처리시간 − 탄소 추정` | 현재 `gold=None`이어서 정답 보상이 유효하게 작동하지 않음 |

코드의 `power`는 kWh로 표기하는 **에너지 추정값**이며 kW 전력과 구분합니다. 출력량 단위와 계수 근거가 검증되지 않았으므로 환경 성과·비용 절감 수치로 사용하지 않습니다.

## 실행 상태

이 저장소는 내려받은 직후 실행이 완료되는 상태가 아닙니다. 코드 구조 확인은 가능하지만 아래 항목을 먼저 복원해야 합니다.

1. [_common_eval](_common_eval), [_common_log](_common_log)는 확장자 없는 파일입니다. 내용을 확인해 Python 모듈로 복원하고 import 이름을 맞춰야 합니다.
2. `env.py`는 `genai`·`types`를 사용하지만 해당 SDK import가 누락되어 있습니다.
3. `env_gemini.py`는 서로 다른 Google SDK를 같은 `genai` 이름으로 import합니다. 사용할 SDK 하나에 맞춰야 합니다. `os.environ` 사용에 필요한 import도 확인해야 합니다.
4. Python, NumPy, Gym, PyTorch, Matplotlib, OpenAI SDK, Google Gen AI SDK 등의 고정 버전 환경을 정리해야 합니다.
5. `GEMINI_API_KEY`는 환경변수로 설정합니다. `main.py`의 예제 `API_KEY` 문자열은 현재 환경에서 실제 사용하는 키 설정이 아닙니다.

위 항목을 정리한 뒤 진입점은 다음과 같습니다. 외부 API 요청·비용이 발생할 수 있습니다.

```bash
python main.py
```

`main.py`는 [data/tasks.json](data/tasks.json)을 읽으며 정책 종류별로 반복 요청합니다. 먼저 소수 작업으로 별도 점검해야 합니다. 같은 환경의 로그를 공유하므로 정책별 결과 경로도 분리하는 것이 좋습니다.

## 산출물과 다음 구현

코드상 결과 경로는 `results/episode_rewards.png`, `results/evaluation.csv`입니다. 이 경로는 **실행 시 생성하려는 산출물**이며 현재 공개된 검증 완료 결과 링크는 아닙니다. 모델 저장 조건도 실제로 동작하는지 확인이 필요합니다.

실질적인 정책 비교를 위해서는 다음 순서가 필요합니다.

- 모델·출력 예산 등 최소 두 가지 이상의 유효한 행동 정의
- 작업별 정답을 보존하고 정답 보상 연결
- Q-learning/QRL의 학습 동작 구현 또는 비교 대상 재정의
- 공급자 실제 사용량과 근거 있는 비용 계수 기록
- 정책별 동일 작업·조건·seed와 결과 저장 경로 분리
- 독립 평가에서 정확도·시간·비용의 균형 비교

현재 단계에서는 성능 순위와 개선율을 제시하지 않습니다. 저장소 목적은 환경·보상·평가 설계를 구체화하고 후속 구현의 기준을 남기는 것입니다.
